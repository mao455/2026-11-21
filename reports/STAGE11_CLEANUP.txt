Stage11 实际清理与保留清单

清理前扫描了正常入口、build 拼接、Python import/动态文件名引用、冻结依赖以及目录占用。保护已有暂存区、未跟踪历史工作及唯一物理记录。没有执行 git reset、git clean 或整目录删除；其他用户项目和生产服务不在清理范围内。

1. 实际删除/无损归档

A. 完成 episode 的动态六路 RGB 数组：76 个 episode、411480 个 NPY，原大小 23,753,917,440 字节；ZIP 留存 6,560,760,389 字节，净释放 17,193,157,051 字节（约 16.01 GiB）。每例 sensor_archive.json 记录数组逐文件 SHA256、ZIP SHA、不可改证据的清理前哈希。归档先逐成员解压核验 CRC/SHA，确认 result/120Hz状态/命令/帧manifest/控制器未改后才删除 NPY。不是删除唯一观测；回放和像素核验可直接读取 ZIP。

B. 8 份 submitted.py：均逐字节等同于各自保留的 episode/program/controller.py，归档 duplicate_submitted_sources.tar.gz。原 1,760,403 字节、归档 443,306 字节，另删已扫描的再生缓存 377,126 字节，合计净释放 1,694,223 字节。逐路径、SHA、恢复命令在 cleanup/source_receipt.json。未删除唯一生成程序。

C. 无引用独立 runner experiments/rax_dexbin_tinyobj/run_stage5.py：扫描仓库 Python 引用为零，先 tar 归档并核 SHA 后移除。原 1,832 字节、归档 1,066 字节，净释放 766 字节。该文件此前未跟踪，故保留可恢复归档；不能凭 Git 恢复它。receipt 在 cleanup/runner_receipt.json。

总净释放 17,194,852,040 字节，包含归档保留成本；不重复计算同一缓存。以上计数仅本轮实际处理，不把历史 Stage9 已完成清理再算一次。3 个超时 episode 的截断原始观测未压缩删除；唯一诊断保留。

在某 episode 目录：
python -m zipfile -e sensor_frames.zip public

恢复前可用 sensor_archive.json 中的 archive_sha256 校验 ZIP。恢复后按 sha256 字典核每个 NPY；原始 manifest 的物理时戳和曝光 q 保持有效。

唯一正常入口 run.py -> run_stage9.main/build；唯一当前 FSM 在 stage5_control.py；感知/候选/IK/共享恢复在 visual_controller.py；曝光配对/控制节拍在 stage9_frames.py / stage9_control.py。build 拼接四文件并写一次显式配置。清除了活跃路径中重复覆盖实现，逐文件 AST 审计没有同名顶层定义；见 cleanup/definition_audit.json。历史 frozen controller 是证据快照，不作为另一份维护中的实现。

新增纳入版本控制：stage5_control.py（原有共享 FSM 文件，不另开 Stage11 runner）、test_stage11_control.py、固定 case/计划、参数冻结与交付文档。修改：visual_controller.py 的快速闭合/本体反馈/局部恢复/按指候选，run.py / run_stage9.py / stage9_control.py / stage9_config.json 的统一 profile 与门控，general_grasp_contacts.py / integration 的同质量选指，stage9_batch.py 的隔离 worker/资源采样/真实后代超时清理，stage9_report.py / replay.py / pixel_compare.py 的计时与无损观测读取，stage10_retrospective.py 的公共/私有证据区分。
